# 转诊资料最小交付

基层与县医院按病情和用途交换最小充分的转诊资料包。

`fixtures/packet_manifest.json` 保存一条经过脱敏的业务样例，源代码只定义读取这份样例所需的最小合同。后续模块应保持既有标识和时间含义，新增状态必须说明迁移方式。

## 模块

- `contracts` — 既有最小数据合同（`packet_manifest.json` 的读取器），保持不变。
- `models` — 条目声明（来源、采集时间、完整性、患者授权）、清单版本、缺失/冲突提示。交接环节固定为 declare → package → transmit → receive → read。
- `rules` — 病种 + 风险等级查表得到必需类目，用途查表得到允许类目；未知组合返回空集，系统不替临床做判断。
- `packet` — 按"病情必需 ∩ 用途允许 ∩ 患者已授权"生成资料包；校验器只输出缺失与冲突提示并定位交接环节。
- `ledger` — 清单版本台账：更正、撤回、复测、紧急升级只追加新版本，已签收版本原地保留、可审计。
- `transfer` — 大文件分片续传（缺口补传、整体摘要核对）；推送以转诊号为键去重，同一转诊只有一条旅程。
- `access` — 按职责解密（角色 → 可读类目）、所见版本回执、超时未读升级。升级为纯通知，合同保证 `scope_expanded` 恒为 False，扩大范围只能走新的清单版本。
- `audit` — 患者查询谁因何用途访问过哪些字段；质控按转诊定位缺项环节，且仅限该转诊当事机构的质控角色，无全量浏览入口。

## 状态迁移约定

- 清单版本原因：`initial` / `correction` / `withdrawal` / `remeasure` / `escalation`，只允许追加新版本，旧版本（含已签收版本）不回改。
- 条目完整性：`complete` / `partial`；"缺失"不作为条目状态，只以校验提示形式出现。
- 加密为合同级模拟（角色密钥派生密钥流），生产环境替换为 KMS 托管密钥 + AEAD，接口不变。
